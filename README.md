# MyCrop Processing

Python/Jupyter processing workflow for **MyCrop**, a UAV-based crop
monitoring project. The workflow processes multispectral and thermal UAV
products, derives vegetation indices and canopy temperature, analyses
their temporal distributions, and produces cell-based crop-stress
information for use in a WebGIS.

## Overview

The processing workflow is organised into 11 Jupyter notebooks. The
notebooks are intended to be run in sequence because later steps use
datasets and outputs generated by earlier steps.

## Data requirements

### UAV flight data

Place the available flight data under `data/`, grouped by year:

-   `data/2025_flights/`
-   `data/2026_flights/`

Keep each flight's original directory and file names consistent with the
paths and naming conventions expected by the notebooks. The exact
internal contents vary by flight and by the products exported from
Pix4D.

### Areas of interest

The `aoi/` directory contains the vector boundaries used by the
workflow:

-   `field_boundary.gpkg`: boundary of the whole field, used by the
    clipping step where configured.
-   `crop_boundary.gpkg`: boundary of the cultivated area, used by
    analyses that focus on the crop area.

These files are inputs, not outputs. Make sure their coordinate
reference systems are compatible with the raster data.

### Intermediate and derived data

The notebooks generate intermediate datasets and derived products,
including aligned rasters, vegetation indices, canopy-temperature
rasters, histograms, Stress Score rasters and cell-based datasets. These
outputs can be large and may be reproducible from the original inputs.

## Environment setup

Python 3 is required. The workflow uses the packages listed in
`requirements.txt`.

From the project root, create and activate a virtual environment.

**Windows (PowerShell):**

``` powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Register the environment as a Jupyter kernel if it is not already
available:

``` powershell
python -m ipykernel install --user --name mycrop-processing --display-name "Python (MyCrop Processing)"
```

Open Jupyter and select the **Python (MyCrop Processing)** kernel for
the notebooks.

## Running the workflow

1.  Put the UAV flight data in the expected `data/2025_flights/` and
    `data/2026_flights/` folders.
2.  Check that the required AOI files are available in `aoi/`.
3.  Open Jupyter from the project and run the notebooks in numerical
    order, from `01` to `11`.
4.  Check the input and output paths in each notebook if your folder
    layout differs from the one documented here.
5.  Confirm that each step has completed and created the expected
    outputs before starting the next dependent notebook.

### Working-directory note

The path configuration in the notebooks assumes that the notebook's
working directory is `notebooks/`. In that case, `Path("..")` refers to
the project root. If you launch Jupyter with a different working
directory, relative paths may resolve incorrectly; set the working
directory to `notebooks/` or adjust the paths consistently.

## Stress Score and grid analysis

Two complementary workflows are provided:

-   **Raster-based stress analysis (Notebook 09):** calculates a Stress
    Score from NDVI, GNDVI, NDRE and canopy temperature for each flight.
    The workflow uses flight-specific percentile thresholds and creates
    stress outputs and annual reports.
-   **Cell-based analysis (Notebook 11):** uses a common 1.5 × 1.5 m
    grid over the cultivated area. It calculates mean indicator values
    per cell, derives a flight-specific cell-level Stress Score, saves
    per-flight GeoPackages and threshold JSON files, and updates
    `grid_analysis/csv/cell_time_series.csv`.

Notebook 10 is a visual comparison of 0.5 m, 1.0 m, 1.5 m and 2.0 m grid
sizes over a selected Stress Score raster. It overlays the candidate
grids for visual inspection; it does not calculate a separate
statistically aggregated Stress Score for each candidate grid size.

**Output note:** Notebook 11 currently defines a path for a Stress Score
GeoTIFF but does not write that file. Its per-flight cell-based stress
output is saved as a GeoPackage, with a PNG preview and a JSON file
containing the thresholds.

## Limitations and notes

-   The workflow depends on the expected directory names, flight naming
    conventions, raster names and coordinate reference systems.
-   Not all output directories exist before the notebooks are run.
-   Notebook 10 compares grid sizes visually using a selected raster; it
    is not a full statistical grid-resolution experiment.
-   Notebook 11's `cell_time_series.csv` is the processing output. It is
    not automatically the same as any separately prepared CSV consumed
    by the WebGIS frontend.
-   Review the paths and required inputs in the notebooks before running
    the workflow on new flights.

## Project context

MyCrop explores the integration of UAV multispectral and thermal
imagery, vegetation indices, temporal analysis and cell-based
crop-stress information in an interactive WebGIS. The processing
workflow is designed to support crop monitoring and research; the
derived Stress Score should be interpreted in the context of the
acquisition conditions, input data quality and the chosen threshold
methodology.
